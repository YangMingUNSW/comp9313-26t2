按顺序照抄命令即可。命令里的路径按 Ed 上常见的 `/home` 填好,可直接粘贴运行。

## 0. 准备:确认文件和当前路径

Workspace 里需要有这些文件:

| 文件 | 作用 |
| --- | --- |
| `proj3.py` | 解法(提交) |
| `A.txt` / `B.txt` | spec 里的样例数据(自检排序 + 格式用) |
| `A_large.txt` / `B_large.txt` | 官方大数据集 |
| `output_d=100_s=0.5.txt` | 官方参考答案(用来比对) |

先看清楚当前目录的绝对路径,后面 `file:///` 要用它:

```bash
pwd
ls -l
```

本教程里 `pwd` 假设为 `/home`,文件都直接放在 `/home` 下,所以 `file:///` 后接 `/home/...`。若你的 workspace 路径不同,把命令里的 `/home` 换成 `pwd` 的真实输出即可。

> ⚠️ **为什么要 `file:///`**:Spark 默认把路径当 HDFS。加 `file:///` 前缀才是读本地文件。
> spec 里给的命令是 `spark-submit proj3.py <input_A_path> <input_B_path> <output_path> <d> <s>`,
> 五个参数;本地测试时把前两个输入和输出都写成 `file:///home/...` 即可。
> ⚠️ **输出目录必须不存在**:Spark 若发现输出目录已存在会直接报错。重跑前先 `rm -rf` 掉旧目录。

## 1. 样例自检(d = 2.0,s = 0.5)—— 先验证格式和排序

```bash
rm -rf out_sample
spark-submit proj3.py "file:///home/A.txt" "file:///home/B.txt" "file:///home/out_sample" 2.0 0.5
```

看结果(`coalesce(1)` 保证只有一个 `part-00000`):

```bash
cat out_sample/part-00000
```

**期望输出**(应与下面完全一致):

```text
(A0,B0):1.000000,0.500000
(A1,B1):1.414214,0.500000
(A2,B0):1.414214,0.500000
```

> ⚠️ **关于小数位数(重要,别被吓到)**:spec 文档里样例写的是 `(A0,B0):1.0,0.5`,
> 但官方发布的参考文件 `output_d=100_s=0.5.txt` 实际是**定长 6 位小数**(`0.500000`、`55.564351`)。
> 评测是拿你的输出和参考文件做**精确 diff**,所以本代码统一输出 6 位小数 —— 你在样例里看到
> `1.000000,0.500000` 是**正确的**,和参考文件的格式一致。文档里的 `1.0,0.5` 只是简写显示。

**这一步顺便验证了:**
- 三对结果都命中(`(A0,B0)`、`(A1,B1)`、`(A2,B0)`),没有多余对、没有漏对。
- 排序正确:按 A 的 ID 数值升序(A0 < A1 < A2)。

## 2. 大数据集(d = 100,s = 0.5)—— 和官方参考答案比对(最关键)

```bash
rm -rf out_large
spark-submit proj3.py "file:///home/A_large.txt" "file:///home/B_large.txt" "file:///home/out_large" 100 0.5
```

```bash
wc -l out_large/part-00000          # 应为 236 行,和参考答案一致
diff out_large/part-00000 "output_d=100_s=0.5.txt"
```

**判读结果:**

- **无任何输出** = 完全一致,✅ 通过。
- 只报**浮点末位极小差异**(如 `...55.564351` vs `...55.564350`)= spec 说浮点精度不影响正确性,✅ 忽略。
- 报**行数不同 / 顺序不同 / 有多余对 / 缺对** = ❌ 真 bug,把 diff 结果贴回来我帮你查。

想只看差了几行、忽略末位小数,可以用(只比对 ID 部分):

```bash
diff <(cut -d: -f1 out_large/part-00000) <(cut -d: -f1 "output_d=100_s=0.5.txt")
```

这一句只比对每行的 `(Aid,Bid)` 部分 —— 如果这里没输出,说明**配对和排序全对**,剩下最多是浮点末位差异。

## 3. 对照评分点自查

| 评分点 | 怎么验证 |
| --- | --- |
| 能编译运行(+6) | 没报错,且有 `part-00000` 输出 |
| 正确性(+4:无多余/无缺失/顺序/数值/格式) | 第 2 步 `diff` 通过 |
| Frequency Sorting(+2) | 代码里全局词频 → `broadcast` 的 token→rank 映射 |
| Prefix Filtering(+3) | 前缀长度 `p = |r| − ⌈s·|r|⌉ + 1`,按 rank 取前缀作 blocking |
| Grid Index(+3) | 格边长 = `d`,B 复制到 3×3 邻域后按 `(token, cell)` 连接 |
| Efficiency(+4) | **不是** 两两(pairwise)比较;无 `cache()`/`persist()`;结果正确才有资格拿这 4 分 |

**特别要肉眼确认的几点正确性:**

1. **两个条件同时满足** —— 输出对必须同时满足欧氏距离 ≤ `d` **且** Jaccard 相似度 ≥ `s`(取等号也算,`≤` / `≥`)。
2. **无重复对** —— 同一对 `(Aid,Bid)` 只能出现一次(代码用 `reduceByKey` 去重)。
3. **排序按 ID 数值**,不是字符串:主键 A 的数值升序,次键(A 相同时)B 的数值升序。所以 `A10` 排在 `A2` 之后。
4. **不是暴力两两比较** —— 靠前缀过滤 + 网格索引缩小候选,避免 O(N²)。

## 常见报错速查

| 报错 | 原因 / 解决 |
| --- | --- |
| `Output directory ... already exists` | 输出目录已存在。`rm -rf out_large` 后重跑 |
| `Path does not exist` / 找不到输入 | 忘了 `file:///` 前缀,或路径写错。用 `pwd` 核对绝对路径 |
| `cat: out_large/part-00000: No such file` | job 没成功,往上翻 spark 日志看真正的异常栈 |
| 结果为空文件 | 输入路径不对读到空数据,或 `d` / `s` 参数写反(顺序是 `... <d> <s>`) |
| `ValueError` / 解析报错 | 输入行格式非 `id#(x,y)#term1 term2 ...`;spec 保证输入规范,通常是路径读错了别的文件 |
